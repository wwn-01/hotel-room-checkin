# 酒店房态与入住协同

围绕「山海旅居」酒店前台入住场景的业务调研与需求挖掘资料集。

核心问题：客房清扫、查房、可售三种状态被压缩进同一个字段，客房部标记「已清扫」后系统即视为可入住，而查房尚未完成，导致前台无法正常办理入住，客人等待、反复核对，甚至换房。

## 关键结论

1. **房态三态需拆分**：清扫完成、查房通过、可售应由查房结果驱动，而非共用一个字段。
2. **查房待办要落到具体接手人**：对方确认接手才算完成，仅发送消息不算。
3. **维修房解除封锁后强制异味复查**：异常一律转人工，需标注触发原因、接手人和确认时间。
4. **AI 只做房态解释与交接提醒**：不自动分房、不开门锁、不处理身份认证。

## 使用说明

`discovery-report.csv` 可直接用 Excel / WPS 打开，字段包含：需求假设、优先级、负责人、状态、验收与约束、证据编号、事实内容。
