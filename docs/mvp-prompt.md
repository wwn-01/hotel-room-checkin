# 山海旅居酒店房态与入住协同｜90 分钟 MVP 开发提示词
## 项目基础
项目名称：酒店房态与入住协同 MVP
技术栈：FastAPI + SQLite + DeepSeek Harness
目标：90 分钟内完成最小可运行闭环演示，支持模拟数据，不强制配置大模型密钥

## 业务闭环（必须实现）
1. 房态规则：清扫完成 + 质检通过 → 可入住；仅清扫未质检 / 质检不通过 / 维修中 → 不可入住
2. 角色：前台、质检、客房调度、管理员，简易权限控制
3. 核心链路：查询房间 → 校验房态 → 不合格自动生成复查工单 → 状态变更写入审计日志
4. 智能体能力：读取知识库 hotel_rule.md，给出工单建议、房态提醒；不能自动办理入住、开锁，异常流转人工
5. 数据：使用模拟房间数据，不需要对接真实酒店系统

## 后端接口清单（FastAPI）
1. GET /rooms：获取全部房间及房态
2. GET /room/{room_id}：查询单个房间详情
3. POST /workorder：创建质检/复查工单
4. PUT /room/{room_id}/status：更新房间状态（清扫、质检、维修、可入住）
5. GET /logs：查询操作审计日志（管理员可见）

## 数据库表（SQLite）
- room：房间 id、房间号、当前状态、备注
- workorder：工单 id、房间 id、工单类型、状态、创建人、结果
- user：用户 id、用户名、角色
- audit_log：日志 id、操作人、操作内容、时间

## Harness 执行流程
1. 加载知识库 docs/knowledge_base/hotel_rule.md
2. 接收用户提问（例如：302 房间能不能入住？）
3. 调用 FastAPI 接口查询房间真实状态
4. 结合知识库规则推理，返回结论 + 工单建议
5. 输出格式：自然语言回答，附带接口返回原始数据

## 90 分钟时间分配
- 0–15 min：初始化 SQLite 表，准备模拟测试数据
- 15–45 min：编写 FastAPI 全部接口，本地启动调试
- 45–70 min：配置 Harness，绑定知识库，绑定接口调用
- 70–85 min：完整链路测试，整理测试样例
- 85–90 min：编写启动命令、验收说明文档
